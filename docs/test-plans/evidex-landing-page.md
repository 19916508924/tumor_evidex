# Evidex B 端 Landing Page 测试记录

## 目标与范围

- 将中英文首页从 ShipAny 脚手架内容改为面向肿瘤基因检测与临床解读团队的 Evidex B 端 Landing Page。
- 首页说明长期产品方向，同时把当前 V0.2 已开放能力、试点方向和规划能力放在对应内容附近。
- 首页体验模块只调用同源 Evidex 接口，选项复用共享查询目录，不维护独立医学结果。
- 顶部导航和页脚隐藏定价、案例、通用 AI 生成器、博客、登录、积分、支付等与当前定位无关的入口。
- 简体中文与英文共享同一信息架构，所有可见业务文案、状态、错误、按钮和可访问名称来自 locale message。

## 验收场景

| 场景     | 输入 / 前置条件                            | 可观察结果                                                                  |
| -------- | ------------------------------------------ | --------------------------------------------------------------------------- |
| 英文首页 | 访问 `/`                                   | 只出现一个英文主标题，显示 11 个主体区块、Evidex 品牌与英文 SEO 信息        |
| 中文首页 | 访问 `/zh`                                 | 与英文页区块、状态和 CTA 意图一致，显示中文产品文案                         |
| 导航收敛 | 1024px 以上桌面端查看导航                  | 单行显示产品价值、工作方式、证据体系、接入方式、FAQ、证据审核和演示申请     |
| 当前体验 | 点击首页体验入口                           | 进入 `/zh/evidence`，英文入口明确当前医学综述为中文                         |
| 真实查询 | 在首屏选择当前支持组合并提交               | 调用 `/api/v1/evidence-answer`，展示接口返回的结构化治疗、证据数和知识版本  |
| 失败状态 | 接口返回无证据、越界、摘要失败或 HTTP 错误 | 显示对应状态，不生成前端预置医学答案，可重试                                |

| 回归     | 访问 `/zh/evidence` 与现有 API             | 原证据体验与后端契约保持不变                                                |

## RED 证据

- `./node_modules/.bin/vitest run tests/unit/landing-content.test.ts`：5/5 失败。失败原因是首页仍使用 ShipAny 品牌、旧区块和不符合 Evidex 的导航及产品数据。
- `./node_modules/.bin/vitest run tests/components/evidex-landing-interactions.test.tsx`：7/7 失败。此时交互组件只有空实现，复制、真实查询与失败状态均不可观察。
- `./node_modules/.bin/vitest run tests/unit/public-product-surface.test.ts`：6/6 失败。静态站点地图仍指向 `your-domain.com`，robots 未隐藏模板路由，四份政策内容仍是 YourAppName 脚手架文案。
- 品牌资产断言补充后先出现 1/7 失败：默认 logo、favicon 与 OG 分享图仍指向脚手架资源；切换为 Evidex 资源后通过。
- 内部界面品牌断言补充后先出现 1/8 失败：后台和循证助手侧栏仍展示未确认的 `your-app-name` 社交入口与 `support@your-domain.com` 邮箱；删除这些占位入口后通过。
- 中文浏览器检查复现页脚路由错误：`当前版本` 指向 `/zh/zh/evidence`。随后在 E2E 中增加 `/zh/evidence` 精确断言，再修复共享本地化链接函数。
- 系统 `pnpm` 是 11.19.0，与仓库要求的 10.x 不兼容，因此 RED/GREEN 的 Vitest 命令先直接调用项目二进制；最终验收使用本地缓存的 pnpm 10.30.3。

## GREEN 证据

- 内容、交互与公开表面聚焦回归：3 个测试文件、20/20 通过。
- 本地化链接回归：11/11 通过，覆盖根路径、锚点、政策页、显式中文路径、外链和相对路径。
- 首页真实同源查询：`NSCLC + EGFR p.L858R` 返回知识版本 `v0.2.0`、4 个治疗匹配、6 条证据结论和 11 条来源记录；前端没有维护独立医学答案。
- 新增受保护模块覆盖率：复制按钮 100%；实时证据组件语句 94.33%、分支 89.18%、函数 100%、行 94.23%；本地化链接函数 100%。

## 完整验收

- `pnpm verify`：通过。类型生成、TypeScript、静态检查、变更文件格式、测试策略、23 个测试文件和 171 个测试全部通过；全体受保护模块语句 97.55%、分支 92.60%、函数 99.41%、行 97.80%。
- `PLAYWRIGHT_CHANNEL=chrome pnpm verify:full`：在无 `.env*` 的临时 Git worktree 中通过。Next.js 生产构建成功，7/7 E2E 通过。
- 当前桌面基线复核 1024px、1280px 和 1440px；检查英文与中文首屏、单行导航、价值区、API 区、真实查询结果和键盘焦点。
- 减少动态效果模式由生产 E2E 验证：主标题和 11 个区块保持可见。
- SEO 验证：英文首页只输出一组 canonical 与中英文 hreflang；站点地图仅发布 Evidex 首页、当前工作台和政策页。

## 不在本次验证范围

- 演示申请的外部线索接收后端和真实商务联系方式尚未由产品确认。本次 CTA 滚动到清晰说明该状态的联系区，不伪造提交成功。
- 企业鉴权、配额、SDK、SLA、自然语言病历、多维患者匹配和临床试验匹配仍不作为已开放能力。
- 英文医学综述工作台尚未建设，英文 Landing Page 会明确链接到中文结果体验。
